1. The Problem & Purpose

In Phase 2, the baseline runner used static, pre-processed Markdown files (`case_study/documents/`). In a real enterprise or municipal environment, data arrives as messy Word documents (.doc, .docx), PDFs with selectable text, and image-only scanned PDFs (like meeting minutes or archived paperwork).

Purpose of Phase 4: Build a robust ingestion pipeline that registers files, extracts text across multiple formats, detects scanned pages, assigns metadata fingerprints, chunks text deterministically, and formats source citations.

2. Exact Code Structure & Files Added

The implementation lives primarily inside rag_core/ingestion/ and rag_core/rag/:

  • rag_core/ingestion/extractors.py — Multi-format extractors (`.doc`, `.docx`, `.pdf`, `.md`) with LVM fallback.
  • rag_core/ingestion/png.py — Handles rendering PDF pages to PNG when text density is too low (< 5 words/page).
  • rag_core/ingestion/service.py — Orchestrates the full ingestion flow (registration, extraction, chunking, storage).
  • rag_core/knowledge/metadata.py — Defines MetadataRecord schema (SHA-256 hashes, timestamps, source location).
  • rag_core/knowledge/chunking.py — Implements words80 (Phase 2 exact baseline) and sections80 policies.
  • rag_core/rag/citation.py — Maps answer stems back to source chunks and pages.

3. Deep Dive into Technical Mechanisms

A. PDF vs. Scanned PDF Detection

When ingesting a PDF, the engine checks the average word count per page. If a page has fewer than 5 words, it is classified as a scan, rendered into a PNG image, and sent to the local Vision Language Model (LVM: glm-ocr) to read the text.

B. Deterministic Chunking (words80 vs sections80)

  • words80: 80-word sliding window with a 15-word overlap. Guaranteed to match Phase 2 baseline chunk texts exactly so experimental metrics remain comparable.
  • sections80: Heading-aware chunking that never crosses markdown headers.

C. Citation Model (rag_core/rag/citation.py)

Small LLMs struggle with long, complex chunk IDs. The citation model outputs short stems (e.g., [D10_bus_fleet_inventory_v2]) while mapping the internal database references precisely.

4. How to Run Phase 4 (CLI Commands)

You can execute ingestion directly via python:

# Ingest the entire city case study (words80 policy)
python -m rag_core ingest-case-study --run-id phase4-words80

# Ingest with sections80 policy
python -m rag_core ingest-case-study --run-id phase4-sections80 --policy sections80

# Ingest a single file manually
python -m rag_core ingest-file path/to/doc.pdf --item D19 --node N6 --version 2 --title "Minutes"
Verification: Run python tools/run_checks.py and pytest tests/test_core_ingestion.py to verify all tests pass.
