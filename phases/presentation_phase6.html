Organizational Hierarchy & Layer Registry

1. The Problem & Purpose

A municipal RAG system cannot treat all documents and departments as flat. Information flows hierarchically from field units up to city departments and the city council. Phase 6 models the municipal organization as a strict tree of nodes and layers with hard invariants enforced by domain workflows.

2. Exact Code Structure & Files Added

Phase 6 implementation spans organizational models, registries, and workflows:

  • rag_core/organization/model.py — The Hierarchy aggregate (manages nodes, parent/child links, terminal flags).
  • rag_core/shared/kernel.py — Defines the TransferRule value object (detail levels, judge scores, confidentiality).
  • rag_core/workflows/organization.py — State-guarding workflows (`OrganizationService`).
  • rag_core/infrastructure/registry_csv.py & sqlite_hierarchy.py — Repositories for loading and persisting hierarchy and layer rules.
  • registry/layer_registry.csv & registry/node_layer_registry.csv — The source-of-truth registry files.

3. Deep Dive into Technical Mechanisms

A. Strict Tree Invariants (Hard Rules)

  • There is exactly **one root node** (City Council).
  • A **terminal node** (black box) cannot have children.
  • A node cannot be moved under itself or its own descendants (preventing circular loops).

B. Layer Transfer Rules (TransferRule)

Each of the 4 layers defines a rule for what it requires when receiving knowledge from below (e.g., minimum judge score, required topics, executive detail level).

C. Use-Case Workflows (Guard Clauses)

OrganizationService refuses any transaction (defining a node, moving a node, making a node terminal) if it violates any hierarchical or document-availability invariant.

4. How to Run Phase 6 (CLI Commands)

# Display current hierarchy and transfer rules
python -m rag_core show-hierarchy

# Initialize hierarchy database from CSV registries
python -m rag_core init-hierarchy

# Define a new node under a parent
python -m rag_core define-node --id N7 --name "New Dept" --parent N4 --field "Transport"

# Move a node under a new parent
python -m rag_core move-node --id N6 --parent N5

# Toggle terminal status (black box mode)
python -m rag_core set-terminal --id N7 --knowledge-db results/ingestion/phase5-words80/knowledge.sqlite
