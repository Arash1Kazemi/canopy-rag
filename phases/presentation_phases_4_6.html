Detailed Technical Breakdown for Class Presentation: Phases 4, 5 & 6

Executive Summary

Project Context & Milestone

Up to Phase 3, we established the Domain-Driven Design (DDD) architecture and core bounded contexts. Phases 4, 5, and 6 represent the core functional implementation of the knowledge pipeline, data evolution tracking, and organizational governance.

Phase 4: Ingestion

Turning raw documents (PDF, DOC, DOCX) into structured, metadata-rich chunks with citation support.

Phase 5: Versioning & Dupes

Tracking document changes, chunk life cycles, and detecting exact, near, and overlapping duplicates.

Phase 6: Hierarchy & Layers

Managing the municipal tree structure, layer registries, transfer rules, and state-guarding workflows.

Phase 4

Document Ingestion Foundation

1. What Was the Purpose?

In Phase 2, we used flat, pre-processed markdown files. Real-world systems ingest messy multi-format files (PDFs, Word docs, scanned pages). Phase 4 built the ingestion engine to parse files, extract text, tag metadata, and assign traceable source citations.

2. What We Built & What Changed

  • Multi-Format Extractors (rag_core/ingestion/extractors.py): Native readers for DOC, DOCX, and PDF. If a PDF has low text density (scanned pages), it automatically triggers local LVM assistance (glm-ocr via rag_core/ingestion/png.py).
  • Metadata Schema (rag_core/knowledge/metadata.py): Every knowledge version carries strict metadata records (author, date, fingerprint, source location).
  • Chunking Policies (rag_core/knowledge/chunking.py): Implemented words80 (80-word sliding window with 15-word overlap, matching Phase 2 baseline) and sections80 (heading-aware chunking).
  • Citation Model (rag_core/rag/citation.py): Generates clean source citations (e.g., [D10_bus_fleet_inventory_v2]) tied back to exact chunk IDs and page numbers.
Key Achievement: A robust CLI command python -m rag_core ingest-case-study that ingests 20+ case study items into SQLite and exports structured CSV catalogs.
Phase 5

Versioning, Chunk Life Cycle & Duplicate Detection

1. What Was the Purpose?

Real documents evolve over time, get copied, or overlap in content. Phase 5 answers three critical operational questions: What changed between versions? What can be retrieved right now? Which documents repeat each other?

2. What We Built & What Changed

  • Change Summary (rag_core/knowledge/changes.py): Computes textual diffs between document versions so Contradictions and updates are explicitly understood.
  • Chunk Life Cycle (rag_core/knowledge/lifecycle.py): Manages chunk stages (created ➔ embedded ➔ checked ➔ indexed), ensuring retired or superseded chunks (like old bus fleet inventories) are excluded from active retrieval.
  • Duplicate & Overlap Detector (rag_core/knowledge/duplicates.py): Detects exact matches (via SHA-256 text fingerprinting), near duplicates, and shared phrase overlaps. Note: Gives advice; human experts decide.
# Run duplicate detection via CLI:
python -m rag_core find-duplicates --db results/ingestion/phase5-words80/knowledge.sqlite
Phase 6

Organizational Hierarchy & Layer Registry

1. What Was the Purpose?

The system serves a municipal organization (City Council, Transport Dept, Water Dept, etc.) arranged in a tree hierarchy across 4 layers. Phase 6 makes this organizational tree usable and mutable under strict domain rules.

2. What We Built & What Changed

  • Hierarchy Aggregate (rag_core/organization/model.py): Manages nodes, parent-child relations, and terminal nodes (black boxes).
  • Layer Registry (registry/layer_registry.csv): Defines layer roles and `TransferRule` parameters (detail level, minimum judge score, confidentiality).
  • Workflows & Guard Clauses (rag_core/workflows/organization.py): Implemented use cases: define-node, move-node, set-terminal. If any rule is violated (e.g., moving a node under itself or violating layer constraints), the workflow refuses the transaction.
  • Persistence: Stored via SqliteHierarchyRepository.
# Example Hierarchy CLI commands:
python -m rag_core show-hierarchy
python -m rag_core set-terminal --id N7 --knowledge-db results/ingestion/phase5-words80/knowledge.sqlite
